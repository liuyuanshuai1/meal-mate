# 一起吃饭叭小程序需求

## 一、项目定位

“一起吃饭叭”是一款面向情侣或家庭场景的微信小程序，主要用于解决“今天吃什么”的日常决策问题，并记录双方一起吃饭的生活内容。

本项目第一版不做外卖、支付、配送、门店等复杂商业功能，而是围绕：

```text
选菜
→ 今晚吃什么
→ 确认晚饭
→ 记录一起吃过
```

这一核心流程进行设计。

项目整体风格偏温暖、轻量、生活化，不做传统电商点餐系统。

------

## 二、前端需求

### 1. 首页

首页主要用于展示：

```text
今日推荐
今天吃什么
最近想吃
今晚安排入口
```

页面顶部标题修改为：

```text
一起吃饭叭
```

原有“店家推荐”等文案修改为：

```text
今日推荐
```

首页支持展示推荐菜品、最近吃过菜品等内容。

------

### 2. 菜单页

菜单页用于展示菜品分类及菜品列表。

支持：

```text
菜品分类切换
菜品列表展示
菜品详情查看
加入今晚菜单
```

原有：

```text
加入购物车
```

修改为：

```text
加入今晚菜单
```

菜品信息包括：

```text
菜名
图片
价格
分类
描述
```

------

### 3. 今晚吃啥页

原购物车页面修改为：

```text
今晚吃啥
```

该页面不作为传统电商购物车，而是作为：

```text
今晚晚饭组合菜单
```

使用。

支持：

```text
查看已选择菜品
删除菜品
修改数量
确认今晚菜单
```

页面底部：

```text
去结算
```

修改为：

```text
就吃这些
```

确认后生成“一起吃过”记录。

------

### 4. 我的页

我的页面用于展示个人信息及功能入口。

支持：

```text
一起吃过
偏好设置
不想吃清单
关于我们
```

历史记录入口名称为：

```text
一起吃过
```

------

## 三、后端需求

后端采用：

```text
Python + FastAPI + PostgreSQL
```

实现。

后端第一版主要围绕：

```text
菜品管理
今晚菜单管理
一起吃过记录
```

进行开发。

后端提供 REST API 给微信小程序调用。

------

## 四、核心业务流程

### 1. 查看菜单

用户进入菜单页后：

```text
获取菜品分类
获取菜品列表
查看菜品详情
```

------

### 2. 加入今晚菜单

用户点击：

```text
加入今晚菜单
```

后，将菜品加入当前“今晚吃啥”列表。

------

### 3. 查看今晚吃啥

用户进入：

```text
今晚吃啥
```

页面后，可查看当前已选择的菜品组合。

例如：

```text
米饭
红烧肉
番茄炒蛋
可乐
```

------

### 4. 确认今晚菜单

用户点击：

```text
就吃这些
```

后，系统生成：

```text
一起吃过记录
```

并清空当前“今晚吃啥”。

------

### 5. 查看一起吃过

用户在：

```text
我的 → 一起吃过
```

中查看历史吃饭记录。

------

## 五、数据库设计

第一版数据库主要包含：

```text
food_category        菜品分类
food                 菜品
dinner_plan          今晚菜单主表
dinner_plan_item     今晚菜单明细
eat_record           一起吃过记录
```

后续可扩展：

```text
user_preference      偏好设置
dislike_food         不想吃清单
```
